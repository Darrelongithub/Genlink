# Audit harness corrections

These notes prevent weak assertions in exploratory drivers from being mistaken for application verdicts. They do not alter application code or replace the recorded responses.

- `learning-loop-browser.json`: the review driver initially required a reviewed topic to disappear from the 72-hour queue. That is not required; a rescheduled topic can remain in the queue. The response does show `reps` 2→3 and a changed `due_at`, so a schedule update occurred. However, a correct self-report also reduced `half_life_hours` 1.14→1.04 and moved `due_at` about 37 seconds earlier. The report treats the direction as PARTIAL and preserves the original failed assertion and payloads.
- `subject-journey-browser.json`: the dashboard/progress assertion was broad, but the recorded Progress text itself contains `Test evidence 5 rows` followed by the five actual item types, skills, scores, and millisecond values. That recorded text is the read-back evidence.
- `preferences-baseline.json`: the driver expected a `chunk_id` on the simple-fallback lesson shape. The returned contract uses `fact_ids`; every block has that field and `why`, and there are no unresolved template markers. The obsolete `chunk_id` assertion is not an application FAIL. The plans establish different first blocks for diagram versus text preferences. They also establish that `fractions` returned `topic_match:false` and generic study-skills concepts; the report does not call that fallback a subject-specific lesson.
- `practice-browser.json`: the first assertion searched a list of opaque `top_…` IDs for the word `biology`, so it returned FAIL despite a relevant queue. The recorded setup and plan show the same topic ID `top_d7b4c258d3c444a08d43` in the chosen subject and all three queue entries, with item IDs including `itm_bio_photosynthesis_00`; no `answer`, `correct_index`, or `answer_spec` key appears. The functional verdict is PASS based on those payloads, not on the bad string search.
- `lesson-player-browser.json`: the finish assertion was broad, but the full recorded review text contains `what you just did`, `you called 0 of 1`, `status finished`, and `f1 ✗ about n/2 not about log2(n)`. Those are the actual review-read-back facts.
- `lessons-browser.json`: the Biology assertion bundled content and gradeability into one check. The payload proves `topic_match:true`, four real Biology concepts, and non-generic cell text, so authored content itself is a PASS. The separate browser reflection run proves that the visible `Your reflection (not marked)` input produces no save or submission; that discarded input remains a FAIL. The report separates those facts instead of calling the Biology text generic.
- `placement-browser-corrected.log`: adding the required Chromium path exposed a race in the standalone script: it read the DOM before the attempt response was rendered and blamed later responses on the wrong question. `placement-browser.json` is the authoritative response-aware rerun: eight `/attempts` responses, all HTTP 200, each followed by its rendered receipt, plus Finish and analyse. It is 9 PASS, not the earlier 11 PASS/7 FAIL.
- Purge probes that queried SQLCipher while the host was running were discarded. Concurrent inspection left the host writing to a deleted WAL inode, so standalone snapshots disagreed with the API. `db-purge-final-before.json`, `db-purge-final-cli.log`, and `db-purge-final-after.json` are the authoritative host-stopped sequence. `db-final-verification.json` was also taken with the host stopped. No application verdict is inferred from the discarded probes.
- `robustness-browser.json` counts both request and response events. The offline request emitted a browser request event but zero responses and one `ERR_INTERNET_DISCONNECTED` failure; the offline PASS is based on the visible error, retained selection, and zero server responses. The final raw snapshot independently shows exactly two stored attempts across the delayed double-click, offline attempt, and online retry.
- `fix-i03-ui-probe.log` supersedes aborted exploratory runs. The driver was stale after phase-1 fixes: it assumed `/subject`, client-visible `run_id`, the removed six-step journey wall, a shared account with no saved subject run, an options-bearing Calculus explanation, baseline radio inputs, and permanently visible More destinations. The final driver uses current routes and owned runs, a fresh scenario guest, a photosynthesis question, pressed-state format controls, one-question baseline cards, and the collapsible More menu. Its 286/286 real result and the separate 281/281 mock result in `fix-i03-ui-probe-mock.log` do not rehabilitate the earlier aborted logs as product evidence.
- `fix-i03-round4.log` and `fix-i03-round4-browser-results.json` are a production functional run with `ADAPT_ART_CHECKS=0`. The old driver assumed the retired subject route, pre-stage questions, instant stage advancement, a combined lesson finish control, and global-header art rules. Those were harness errors. Art overlap and gzip values remain observations only; both art verdicts are NOT RUN.
- `fix-i03-round6-items.log` keeps the second subject in the existing Add-a-subject chooser instead of reloading and restoring the completed first run. Real-plan drag-match and other item answers use only public controls; no answer key is required to read the server verdict. `fix-a06-access-entry-current.json` uses the current explicit Save-choice/guest flow and records 17 gated routes, zero creation requests before entry, and one after entry.
- `fix-i03-games-e2e-all.log` replaces the removed `/subject` outline/map driver with current sealed-plan, public-control, and evidence-read-back assertions; it does not delete the subject project. The partial snapshot now requires learner-facing `locked box` and `not measured` copy and rejects the internal `locked_box` key. Final counts are 9 passed, 2 intentionally skipped desktop-only duplicates, 0 failed across desktop, mobile, and keyboard.
- `fix-i03-journey-full-scripted-fake.log` uses the current journey card, CSRF-protected stage receipts, and first-lesson Finish control. It retains the written-for-you upgrade, chosen-answer explanation, two different reteaches, and server-state assertions. Both desktop and mobile pass. This is scripted-fake integration evidence only, not real model evidence. `fix-i03-round6-crawl.log` separately records 90 clean page checks and a passing rapid-switch run.
